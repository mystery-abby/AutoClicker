# 自动点击器 (AutoClicker)

Android 手势自动化工具：**录制脚本 → 回放 → 定时执行**。使用无障碍服务派发手势，无需 Root。

## 功能

- **脚本录制**：屏幕上直接操作，点击 / 长按 / 滑动自动记录成动作序列（全屏浮层 + 手势回放，录制过程中目标界面照常响应）
- **脚本编辑**：动作列表可逐条删除、修改每个动作的间隔时间；可设置循环次数（0 = 无限循环）
- **立即回放**：从列表或编辑器一键运行，前台服务 + 通知栏实时显示进度
- **悬浮停止按钮**：运行期间屏幕右侧浮出红色圆形按钮，显示 `当前/总数` 进度，点一下即停；可拖到任意位置并**记住上次位置**；**长按可临时隐藏 3 秒**，让出被挡住的点击区域
- **定时执行**：支持三种模式
  - 仅一次（指定日期时刻）
  - 每天（指定时刻）
  - 工作日（每周一至周五的同一时刻，自动跳过周六日）
  - 按间隔（每 N 分钟）
- **开机自恢复**：重启或应用更新后自动重新登记全部定时任务
- **本地存储**：脚本与定时任务以 JSON 保存在 SharedPreferences，无网络权限

## 环境

- 编译：JDK 17+，Android SDK Platform 34，Build-Tools 34.0.0
- 运行：Android 8.0 (API 26) 及以上
- 已在 `local.properties` 中配置 `sdk.dir`

## 构建

```bash
cd E:/my-project/AutoClicker

# 调试包
./gradlew assembleDebug          # app/build/outputs/apk/debug/app-debug.apk

# 正式包（使用仓库内 release.keystore 签名）
./gradlew assembleRelease        # app/build/outputs/apk/release/app-release.apk
```

签名信息见 `keystore.properties`，密钥库为项目根目录的 `release.keystore`
（alias `autoclicker`，口令 `autoclicker123`）。**公开发布前请替换为你自己的密钥库。**

## 首次使用

1. 安装 APK 后打开应用，首页顶部会出现黄色提示条
2. 点「去开启」，在 **设置 → 无障碍 → 已下载的服务** 中打开「自动点击器」
3. 回到应用，提示条消失即表示就绪
4. Android 13+ 首次运行会请求通知权限（用于显示运行状态）
5. Android 12+ 如需准点执行定时任务，请允许「闹钟和提醒」权限（定时对话框内会提示并可跳转）

## 使用流程

**录制**

首页 → 新建脚本（或已有脚本点「录制」）→ 应用退到后台并弹出录制浮层
→ 在任意 App 上操作 → 点浮层上的「完成」→ 自动保存并回到编辑器

录制浮层顶部的控制条可拖动，避免遮挡要点击的区域。长按超过系统长按阈值记为长按动作，
有明显位移记为滑动，其余记为点击。每个动作之间的实际间隔会被记录下来。

**编辑**

编辑器里可修改脚本名、循环次数；每个动作右侧的「间隔 xxx ms」可单独调整，
删除按钮移除单个动作。间隔指的是**该动作执行完后等待多久再执行下一个**。

**立即运行**

列表里点 ▶ 或编辑器里点「运行」。运行期间通知栏显示 `第 n / 总数`，点通知里的「停止」即可中断。

**定时执行**

列表里点「添加定时」或切到「定时任务」标签页 → ➕：
选择脚本、选择重复方式、设置时间或间隔 → 保存。
定时任务列表中可用开关随时启停，删除任务不会删除脚本。

## 实现要点

| 关注点 | 方案 |
| --- | --- |
| 手势派发 | `AccessibilityService.dispatchGesture()`（`GestureDescription`） |
| 录制浮层 | `TYPE_ACCESSIBILITY_OVERLAY` 悬浮窗（无需「显示在其他应用上层」权限） |
| 录制时界面仍可操作 | 浮层拦截手势 → 生成 `Action` → 立即用 `dispatchGesture` 回放给下层 App |
| 播放保活 | 前台服务（`specialUse` 类型）+ 低优先级常驻通知 |
| 精确定时 | `AlarmManager.setExactAndAllowWhileIdle()`，无权限时降级为 `setAndAllowWhileIdle()` |
| 重复任务 | 每次触发后重新排下一次（DAILY 按当天毫秒偏移重算，INTERVAL 按间隔顺延） |
| 开机恢复 | `BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` 广播中重新登记全部闹钟 |
| 数据存储 | SharedPreferences + Gson，脚本与定时任务分别序列化 |

主要代码位置：

```
app/src/main/java/com/qian/autoclicker/
├── data/          Models.kt（Action/Script/Schedule）· Repository.kt（JSON 持久化）
├── service/       ClickAccessibilityService.kt（手势派发与播放）
│                  RecorderOverlay.kt（录制浮层）
│                  PlaybackService.kt（前台服务与通知）
├── schedule/      Scheduler.kt（AlarmManager 调度）· AlarmReceiver.kt · BootReceiver.kt
└── ui/            MainActivity.kt · ScriptEditorActivity.kt · 各 Adapter 与对话框
```

## 已知限制

- **坐标是绝对像素**：脚本在分辨率或屏幕方向不同的设备上回放会偏移。录制与回放请使用同一台设备、同一屏幕方向。
- **部分系统界面无法操作**：出于安全限制，无障碍手势无法点击系统权限弹窗、锁屏密码键盘等界面。
- **国产 ROM 保活**：小米 / 华为 / OPPO / vivo 等系统可能清理后台进程，需在系统设置里为本应用关闭电池优化、允许自启动，定时任务才可靠。
- **录制时的手势延迟**：录制的每个手势都要经过浮层转发再回放，实际操作会有轻微延迟，属正常现象。
- **间隔上限**：单个动作间隔建议不超过 60 秒；手势本身持续时长受 `GestureDescription` 限制（最长约 60 秒）。

## 常见问题

**点「录制」闪退，之后提示「请先开启无障碍服务」**

根因：录制浮层用 Service 的 Context 加载含 `MaterialButton` / `?attr/...` 的布局，
而 Service Context 不带 App 主题，inflate 时抛 `InflateException` 导致进程崩溃；
进程一挂，系统就解绑无障碍服务，于是首页显示成「未开启」。两个现象是同一个 bug。

已修复：浮层改用 `ContextThemeWrapper` 套用应用主题；`startRecorder` 全程 try-catch，
失败时弹提示而不是崩溃。

**开启了无障碍仍显示未开启**

先长按首页标题下方的状态文字，会弹出诊断信息（可复制）。里面有 6 项系统真实状态，
能直接看出是「系统没记住授权」还是「服务没连上」。若 ④⑤ 显示为空，说明授权没生效：

1. 到 设置 → 无障碍 → 已下载的服务，把「自动点击器」**关闭再重新打开**
2. 某些 ROM（MIUI / EMUI / ColorOS）需要额外确认「允许」弹窗，重启后需重新授权
3. 检查是否被第三方省电管家或无障碍快捷方式限制

**录制时计数疯涨、目标 App 一直打不开**

根因：`dispatchGesture` 注入的手势只会被**最上层可触摸窗口**消费。全屏录制画布若在回放期间
仍可触摸，注入的手势会再次触发录制逻辑，形成"记录 → 回放 → 再记录"的无限循环。

已修复，三重防护：

1. 回放前给画布加 `FLAG_NOT_TOUCHABLE`，让手势直达下层 App，回放结束再恢复
2. 回放期间用 `suppressTouch` 直接丢弃落到浮层的触摸（堵住标志生效前的竞态窗口）
3. 回放延迟 30ms 启动，给 WindowManager 留出应用标志的时间
4. 用 `touchAccepted` 保证 DOWN 被丢弃时，后续 MOVE/UP 也不会用陈旧坐标生成错误动作

**无障碍总是被系统关闭**

有 4 个原因，本次已修前 3 个：

1. **事件监听过宽**（已修）：原来 `accessibilityEventTypes="typeAllMask"`，系统每次界面变化都往本应用投递事件，高负载被 ROM 判定为耗电而关闭。本应用用不到任何无障碍事件，现改为只监听 `typeWindowStateChanged`。
2. **进程崩溃**（已修）：协程无异常处理器、`dispatchGesture` 无 try-catch，任一手势异常都会崩掉进程 → 服务被解绑。现已全链路兜底，异常只记日志。
3. **进程被回收**（已修）：新增 `KeepAliveService` 前台守护服务，无障碍开启时自动运行，每 5 秒校验状态，开机自动恢复。
4. **ROM 省电策略**（需手动设置）：国产系统的自启动/后台清理只能由用户授权。首页会显示蓝色提示条，点「去设置」按引导操作。

**Android 不允许应用自己重新开启无障碍**（系统安全限制，防止恶意软件），所以 4 只能靠用户设置。

**点运行没反应，过很久才突然执行**

两个原因，均已修复：

1. **首个动作的间隔被录成了"犹豫时间"**：`lastActionTime` 在浮层创建时就初始化，第一次点击的间隔 = 你打开浮层后想了多久。想 30 秒，回放就先干等 30 秒。现改为首个动作间隔固定 0，其余间隔上限 10 秒。**旧脚本会在首次读取时自动修正并写回**，不用重录。
2. **启动失败被静默吞掉**：无障碍实例为 null 时原来直接 `stopSelf()`，用户毫无反馈。现在会先无条件进前台（避免 Android 12+ 的 5 秒 ANR），等待服务绑定最多 3 秒，失败则弹通知和 Toast。

另外：单次手势被系统取消不再中断整个脚本（连续失败 5 次才停）。

**回放时滑动/画出的轨迹不生效，界面不滚动**

有 4 个原因，均已修复：

1. **轨迹被记成了「回到主界面」**（已修）：原来只要"起手在屏幕底部 64dp 内 + 向上滑超过屏幕 30%"
   就判定为回桌面，从列表底部往上拖动滚动的动作会被误记，回放时执行的是回桌面而不是滚动。
   现在额外要求终点落在屏幕上半部分、且手势基本垂直才判定为回桌面。
2. **轨迹里有重复采样点**（已修）：相邻点距离为 0 的零长度线段会让部分 ROM 判定路径非法，
   整条手势被静默丢弃。构建 Path 前会去掉重复点。
3. **手势太短/太快**（已修）：按下就甩出的滑动录制时长可能只有几十毫秒，部分 ROM 会直接取消；
   轨迹很长而时长极短时注入速度也会超限。现在滑动时长保底 150ms，并按最高 2.5px/ms 反推时长。
4. **多段路径不被支持**（已修）：部分 ROM 对多段 Path 支持差，只走第一小段或整条取消。
   点数会均匀重采样到 32 个以内；若仍被系统取消，自动退化为「起点→终点」直线重试一次。

**录制正常，回放画的曲线（手势密码之类）不生效**

排查顺序：

1. 先在**普通页面**（比如备忘录的画布）录一段曲线回放。普通页面能画出来，说明回放链路本身正常。
2. 普通页面正常、唯独密码界面不行 → 该界面被系统安全机制拦截，**无解**：
   - 系统锁屏的图案/密码输入界面：Android 禁止无障碍手势在安全锁屏上注入触摸；
   - 银行 / 支付类 App 的手势密码页、安全键盘：这类页面通常设置了 `FLAG_SECURE`，
     系统会拒绝模拟触摸进入。录制时"正常"是因为那是你真实的手指，回放用的是注入手势，
   - 两者都是系统级限制，任何无 root 的应用都无法绕过。
3. 普通页面也画偏/画不出来 → 是轨迹坐标问题，本次已修复：录制时轨迹中段采样点原先是
   View 相对坐标、起终点是屏幕绝对坐标，窗口原点不与屏幕重合的 ROM 上曲线中段会整体偏移；
   现已统一换算为屏幕绝对坐标。
4. 回放中被系统拦截时，现在会弹 Toast 明确提示（连续失败达到阈值自动停止），不再静默。

**之前能解锁手机，现在不行了（解锁脚本回放卡住）**

根因：新增的「回到主界面」手势判定，把"从屏幕底部上滑、幅度超过屏幕 30%"的动作记成了
回桌面。锁屏上的"上滑划开锁屏"恰好就是这种手势——回放时执行的是
`GLOBAL_ACTION_HOME`，而这个动作在锁屏上完全无效，解锁脚本卡在第一步，图案根本画不上。

已修复：

1. **录制**：检测到前台是锁屏（SystemUI keyguard）时，上滑不再记成「回到主界面」，照常记为滑动；
2. **回放**：执行「回到主界面」动作时如果发现当前在锁屏上，且该动作保留了录制轨迹，
   自动改按普通滑动手势回放（划开锁屏）——旧脚本无需重录即可恢复解锁；
3. 老脚本若上滑已被记成「回到主界面」，装新版后直接回放即可，无需重新录制。

**装新版本**

直接用新 APK 覆盖安装即可，脚本和定时任务会保留（同一签名）。
